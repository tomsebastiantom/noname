feat(k8s): the API and worker run in the cluster; compose is stopped

The cluster is now the only stack. Verified from inside the pod:

  /ready  -> {"ready":true,"checks":{"database":true,"analyticsReady":true}}
  /health -> status ok, redis subsystems {event-bus,sse,collab-relay} all true
  logs    -> tracing to http://jaeger:4318, "Server running at http://localhost:3000"

Compose is stopped (`podman compose down`, volumes kept), freeing the duplicate
infrastructure: 3.2 GB used, 4.2 GB available.

Six defects found getting here, each fixed and documented rather than worked around:

1. `pnpm exec` re-installed the workspace at every container start (21 s + network).
   The image now calls /app/node_modules/.bin/tsx directly, and
   `packageManager: pnpm@11.12.0` is pinned at the root so the container cannot pick
   a different major than the host (observed: host 11.12.0, container 12.16.1).

2. The image baked in .env: COPY . . carried packages/server/.env and load-env
   injected 9 vars at startup - credential leakage plus stale localhost URLs
   shadowing the Secret. Fixed by excluding every .env from the build context.

3. Excluding .env then removed required config: the R2/S3 asset vars live only in
   packages/server/.env, so the API crash-looped with "Asset storage requires R2/S3
   config". The real fix is scripts/cluster-env.mjs, which flattens BOTH env files the
   way load-env does (root wins, package-local fills gaps) and rewrites loopback to
   Service DNS - keeping ZITADEL on localhost:8080 because the socat sidecar serves it
   there.

4. kubectl apply pruned the Secret: declaring noname-env inside api.yaml deleted the
   25 keys the generated Secret had. CLICKHOUSE_URL vanished and analytics silently
   fell back to http://localhost:8123 while the pod looked healthy. The Secret is now
   created out-of-band and appears in no manifest.

5. Jobs are immutable: changing the migrate Job's command fails with "field is
   immutable"; delete and recreate.

6. (Previous commit) service-link env injection and floating image tags.

`scripts/cluster-env.mjs` is committed; its OUTPUT (.env.cluster) is gitignored and
must never be tracked - a first attempt to commit it was rejected by push protection,
which is why the ignore rule and this note exist.

Also records the edge answer: the worker is a Cloudflare Worker, production is
`wrangler deploy` to Cloudflare, and the cluster runs `wrangler dev --local` only so
the local stack is complete. Self-hosting workerd is possible (a Helm chart exists)
but means re-implementing KV/R2 - a project, not a Dockerfile.
