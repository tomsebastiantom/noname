docs: document the environment model and the decisions behind it

The model, stated once so it stops being re-derived in conversation:

  local (this developer)   infra + browser fleet in k8s; services on the host via pnpm dev;
                           client via rspack dev; edge via wrangler dev
  local (contributors)     the same, but infra in compose - kept as a first-class path
  staging / production     everything in k8s except the edge, which is Cloudflare

Services stay on the host deliberately. The cluster is there for two reasons only: the
browser fleet (cgroups isolation per browser, /dev/shm sizing, /pressure autoscaling -
none of which compose can do) and proving that the manifests work. It makes service
iteration slower, not faster, which is why api/worker never move into it locally.

Because there is no NodePort (it binds every node's IP and bypasses Ingress/TLS/policy),
host services reach cluster infra through nine explicit port-forwards. That is also why
.env needs no rewriting: port-forwarding already makes the cluster look like a local
server. Documented, including the failure mode people trip over - a dropped zitadel
forward surfaces as `invalid assertion`, not as a network error.

The compose file is inventoried rather than assumed: nine services and their ports, the
two one-shot helpers, the three volumes, and the warning that compose and the cluster are
alternatives, not layers (~1.9 GB each).

Manifest layout: kustomize base + overlays, not Helm. It is built into kubectl, we do not
package for third parties, and it gives the property that matters - a local-only setting
cannot reach production, because it lives in overlays/local and base/ does not contain it.
Noted as pending, since today everything is one flat set with dev values inline.

Also records the seven things standing between this and a real staging environment, the
promotion path (promote digests, never rebuild - a rebuild silently changes what was
verified), and a decision log covering every choice made in this session with its reason
and status.
